# 解释那个数字（Explain the Number）

> 翻译自 `skills/principle-explain-the-number/SKILL.md`。本译文仅供人阅读，Agent 执行时读英文原文。术语见 [GLOSSARY.md](../GLOSSARY.md)。
>
> 技能名 `principle-explain-the-number`（frontmatter 的 `name` 字段，寻址键，绝不汉化）。

---

**适用时机**：测量之前，以及信任、汇报、据以行动某个你测出的数字之前：加速、回退、吞吐、延迟、eval 结果。找出限制它的是什么，并排除它测量的其实不是你以为的那件事。

- **跑之前写下决策。** 点名什么结果会改变决策，以及噪声地板。run-to-run 波动大于效应时就停。
- **问"为什么不是两倍？"** 点名限制结果的资源或代码路径：一个核、一把锁、磁盘、网络、或压测器本身。从 profile 或运行期间的系统计数器拿它，再映射到源码。读代码得出的猜测不是限制器。说不出数字为什么没好两倍，你就不知道自己测了什么。
- **列出这个数字还可能在测什么，逐个用证据排除。** 常见嫌疑：错误、被跳过或缓存的工作、从未运行的代码、未调优的一侧（留在默认设置）、噪声、以及端到端太小不足道的一段。
- **证据与数字放在一起。** run 数、波动、限制器，写进笔记或链接的制品。

性能数字按 [benchmark-checklist](./benchmark-checklist.md) 技能跑完整流程。eval 结果对试次问同样的问题：每次 run 都做了任务吗、差距跨试次与模型都成立吗、场景重要吗。

你跳过了本条，当：run 开始时没写下会改变决策的结果；数字背后的证据没有 run 数、没有波动、没有点名的限制器；或省下的时间大于被改那一段原本花的时间。

区别于 [Prove It Works](./principles.md)（检查输出是真的）。
