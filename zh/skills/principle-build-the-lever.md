# 造杠杆（Build the Lever）

> 翻译自 `skills/principle-build-the-lever/SKILL.md`。本译文仅供人阅读，Agent 执行时读英文原文。术语见 [GLOSSARY.md](../GLOSSARY.md)。
>
> 技能名 `principle-build-the-lever`（frontmatter 的 `name` 字段，寻址键，绝不汉化）。

---

**适用时机**：任何非平凡工作，不只批量工作：编辑、迁移、分析、检查。造那个能做它或能证明它的工具（codemod、脚本、生成器、或你的子智能体遵循的技能），而不是手工做。这个工具就是审阅者能重跑的制品。

工作不平凡时，造那个能做它的工具，而不是手工做。

codemod、生成器或脚本每次以同样方式做这份工作，且重跑免费。这个工具是审阅者可以读并重跑来核对工作的一个制品。手工变更只能靠重做来复验。确定性脚本把"信我"变成"跑这个"。

默认造杠杆。只有任务是平凡的——几处一眼就能看完的显然编辑——才跳过。

- 先手工做第一个单元来学会配方，然后造工具。在那一个单元上重跑工具、diff 你手工的版本来证明它。让杠杆可以安全重跑。
- 编辑用 codemod 或脚本，重复文件用生成器，分析用灌进 sqlite 的查询，验证用可重跑的检查。
- 确定性杠杆胜过 fan-out。工具能一遍处理所有单元就自己跑。不要派一堆委派者去手工应用一个脚本能做的事。
- 把工作派给子智能体时，把杠杆写成它们都读的技能：配方、验证契约、不可触碰的围栏，一个制品。放在委派者的写权限之外，让它们没法悄悄改契约。
- 应用本原则会产出一个文件。若你引用了它而 diff 里没有 codemod、脚本、生成器或委派技能，你就是没应用它。
- 工作活得比会话长时，把杠杆提交入库。

门槛是平凡性，不是重复性。当杠杆正是让工作可检查的东西时，一次性工作也值得一个杠杆。按 [Laziness Protocol](./principles.md)，造能做或证明这件事的最小脚本，绝不是一个框架。
