# 串成可验证单元（Sequence Work into Verifiable Units）

> 翻译自 `skills/principle-sequence-verifiable-units/SKILL.md`。本译文仅供人阅读，Agent 执行时读英文原文。术语见 [GLOSSARY.md](../GLOSSARY.md)。
>
> 技能名 `principle-sequence-verifiable-units`（frontmatter 的 `name` 字段，寻址键，绝不汉化）。

---

**适用时机**：多步骤工作（清扫、迁移、成串同类编辑）及 commit 与 PR 的堆叠方式。把工作拆成每步以可检查状态收尾的小单元，逐个检查再进下一个，排序交付让序列向审阅者自我证明。

把工作排成小单元的序列，每个单元以一个你能检查的状态收尾，当前单元不绿就不前进。

**为什么**：在肇事的单元被抓住的破坏，定位很便宜。批次之后才被抓住的破坏已被埋住，而你已经在坏基座上继续建了。把这些单元排成审阅者可重放的交付，把"信我"变成"看它先红后绿"。

**执行。** 清扫、迁移或任何成串同类编辑里，先验证每个变更再开始下一个。每个单元是一个前后括号：已知好状态、一个变更、跑检查、再前进。先 rebase 到干净 trunk，让每次检查都对真实基线。有杠杆做编辑时，逐单元检查几乎免费。也要跑。

**交付。** 按能证明工作的顺序堆叠 commit 与 PR。标准形态是失败测试在下、修复在上。其他叙事顺序：重塑之前先减法、处理之前先采基线、功能之前先脚手架。每个 commit 独立可落地，序列读起来像一段论证。

它是 **prove-it-works** 原则技能（让每次检查为真）与 **build-the-lever** 原则技能（让逐单元检查便宜）的排序互补。
