# 测行为不测实现（Test Behavior, Not Implementation）

> 翻译自 `skills/principle-test-behavior-not-implementation/SKILL.md`。本译文仅供人阅读，Agent 执行时读英文原文。术语见 [GLOSSARY.md](../GLOSSARY.md)。
>
> 技能名 `principle-test-behavior-not-implementation`（frontmatter 的 `name` 字段，寻址键，绝不汉化）。

---

**适用时机**：写、改、保留一个测试时。断言代码使用者能观测到的东西，让行为坏时测试失败、仅内部变化时测试保持通过。

测试是对"代码为其使用者做什么"的主张：一个调用方、一个终端用户、或另一个服务。行为是这些使用者通过他们使用的接口能观测到的东西：返回值、错误、能读回的状态、对代码之外系统的影响——一个发出的请求、一行写入、一条消息。实现是他们观测不到的：私有助手、内部调用顺序、中间数据、哪个内部协作者干了活。

用两个假想编辑审判每个测试：

- **破坏行为。** 让代码返回错误值、跳过一个效果、或把效果做两遍。测试仍通过，它就什么都没证明。常见原因：断言松于契约、期望值由被测代码计算、复述从不运行读取它的代码的常量或提示词字符串、对测试自己构造的数据做断言。
- **改内部。** 保持所有可观测结果不变，重构底下的代码。测试现在失败，它就钉死在实现上。每次重构都要重写，却仍抓不到缺陷。

保留能抓住第一个编辑、并活过第二个编辑的测试。重写或删除其余。写出两者兼备的测试：通过使用者的接口以具体输入驱动代码。期望值从需求派生，不从代码的一次运行派生。断言契约承诺的东西，不多不少。

契约说了算，不是断言的形状。"空购物车永不扣款"是承诺时，"支付客户端没被调用"的断言就是行为。配一个确实扣款的用例，让测试证明它看得见调用。被 mock 的外部服务收到的载荷是行为，因为那个服务观测它。对内部助手的调用是实现，因为没有使用者看得见。空列表在"无记录匹配"时是精确答案，在"测试只需要随便一个结果"时是空壳检查。精确的错误信息钉死了没有调用方读的措辞。调用方据以分支的错误类型才是契约。

测试可以钉一个不变式而不是一次调用，如一个键必须存在于两张表、或一个编译期类型检查。不变式就是行为。
